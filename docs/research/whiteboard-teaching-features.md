## 0. 执行摘要

1. **现状**：云砚白板是基于 Konva + Yjs 的自研白板，已具备教师独占书写、页码/视口同步、PPT/PDF 课件导入、基础绘图工具，但**笔迹零持久化**、**无任何学科工具**，且存在一批影响教学质量的缺陷（见第 1 章）。
2. **竞品结论**：国内教学白板（希沃、ClassIn）的差异化核心是**学科工具集 + 课件生态 + 板书保存回放**；动态数学能力（GeoGebra）自研成本极高，是"外挂 vs 自研"的关键分水岭。
3. **技术路线建议**：**继续自研 Konva + 分层外挂领域库**，不整体替换白板引擎。理由：现有 tldraw / Excalidraw 均为 React 组件（与本项目 Vue 3 栈冲突）、tldraw 生产环境需付费商业授权、现有 Yjs 协议（页/视口/课件/角色）已深度绑定。详见第 5 章。
4. **优先级**：先做**阶段 0 缺陷修复**（类型枚举统一、undo 迁移、legacy paint-log 链路移除、类型治理基线），再落地 **Must 6 项**（板书持久化（消化 D1/D7/D8）、板书导出、远端光标显示、公式输入、荧光笔、课件页全工具回归）。
5. **清单规模**：Must 6 项、Should 16 项、Could 16 项、Won't 4 项（详见第 7 章）。
6. **重要假设**：教师端为**键鼠齐备的常规办公机**（触摸一体机为边缘场景，修饰键交互需替代方案，见 4.9 状态矩阵）、班级 ≤50 人、yjs-ws-service **单实例部署**；需求推演来自竞品反推与教学常识，**未经真实教师访谈验证**，阶段 1 开工前须过教师走查硬门（第 10 章 Q7）。
7. **验收与门禁**：全部功能条目按 **4.8 五维 DoD**（正常/边界/异常/权限/兼容，含量化阈值与环境矩阵）+ 4.9 状态矩阵验收；**上一阶段全绿才进下一阶段**（签批人：产品负责人 + CTO）；三项前置硬门：教师走查（阶段 1 前）、数据合规/法务会签（F6.1–F6.3 上线前）、渲染方案 spike（F1.1 立项前）。开放问题 **Q1–Q11 待拍板**（见第 10 章），清单改动一律走第 11 章变更流程。

**成本档定义**（单人）：小 ≤1 周 ｜ 小-中 ≤2 周（半档）｜ 中 1–4 周 ｜ 中-大 2–6 周（半档）｜ 大 >4 周或需**协议改动/新增服务端存储依赖** ｜ 极大 = 需要专用引擎或外部资源库授权。**附加因子**：新增运行时依赖须单独标注（含包体与许可审查），不直接升档；高风险条目给"区间值 + 升档触发条件"（如"中，若含多实例路由与留存策略则升大"）。

## 1. 现状盘点

### 1.1 架构现状

| 层     | 现状                                                                                                                       |
| ------ | -------------------------------------------------------------------------------------------------------------------------- |
| 渲染   | Konva 自绘 canvas，`KonvaRenderer.ts`（形状工厂 + 视口/激光层）                                                            |

| 角色   | 教师可写、学生只读（`readOnly = !isTeacher`），学生跟随教师页码与视口                                                      |

### 1.2 现有能力清单（已有，不重复排期）

- 工具：选择/拖拽/缩放、画笔、橡皮、文本（双击编辑）、矩形/圆/箭头/直线（Shift 约束）、图片上传、激光笔（awareness 广播）、平移缩放/适配视口

- 教师控制：清页、课件上传、激光笔

### 1.4 与"教学白板"目标的差距总结

以教学白板的五要素对位现状（● 达标 ｜ ◐ 部分 ｜ ○ 缺失）：

| 要素         | 现状 | 差距说明                                                         |
| ------------ | ---- | ---------------------------------------------------------------- |
| 板书基础能力 | ◐    | 有笔/形状/文本，但缺荧光笔、图形规整、表格、对齐吸附等教学高频件 |
| 学科工具     | ○    | 公式、坐标系、几何、学科图形全部缺失（C1/C2/C3 三个能力域 0 项） |
| 课件融合     | ◐    | 课件能进、能画，但从未按"全工具可用"验收（F5.1 的由来）          |
| 沉淀与回放   | ○    | 零持久化，下课即失（D1/F6.x 的由来）                             |
| 学生端体验   | ◐    | 有跟随（页/视口），无光标、无课后回看（D2/F7.1/F6.3）            |

**一句话结论**：现状是一块"能实时同步的空白板"，距离"教学白板"的差距集中在**学科工具**与**沉淀回放**两条主线——恰好对应第 4 章 C1–C3 与 C6 两个能力域。

## 2. 竞品调研

> **采信前提（评审新增）**：本章为桌面研究（附录 C）。在附录 C"实机抽验各 30 分钟"完成前，**2.1/2.3 章的工具清单与数字标注"待核"**——本章结论驱动第 4 章优先级，抽验未过前不得作为升档/立项的唯一依据。

### 2.1 重点深拆 A：希沃白板 5（国内大屏教学标杆）

**产品定位**：备授课一体化的互动课件工具，绑定希沃硬件生态，累计 800 万教师用户（官方口径）。

**交互流程拆解**（备课 → 授课 → 课后）：

1. **备课**：云课件新建 / PPT 导入（PPT 以图片+动画解析模式导入，≤300 页，>99 页可能失败）→ 元素级云同步 → 拖拽插入学科工具、思维导图、课堂活动模板。
2. **授课**：全屏授课模式，工具栏随时调用学科工具（板中板、蒙层、克隆、计时器）→ 板书实时"智能笔迹保存" → 手机扫码控制大屏/拍照上传学生作业。
3. **课后**：板书与课件云端保存；"知识胶囊"录制带时间轴的可交互微课，支持分享回看。

**学科工具矩阵**（官方宣称 19 种学科工具，覆盖 K12 各学段）：

| 学科 | 工具                                                                                        |
| ---- | ------------------------------------------------------------------------------------------- |
| 语文 | 汉字笔顺（5166 字动态字库，教师共建扩充）、拼音标注/多音字、古诗词解析（作者/朗读一键插入） |
| 数学 | 几何画板、公式编辑器、函数图像、数学画板（800+ 动态演示资源）、直尺/圆规仿真                |
| 英语 | 四线三格、英汉词典、智能拼写、听写（标准发音自动朗读）                                      |
| 物理 | 电路仿真、星球模型、仿真实验                                                                |
| 化学 | 化学方程式工具（教师逐条共建的全学段方程式库）、虚拟实验                                    |
| 通用 | 思维导图、表格、思维模板、地理图解、题库（30 万+）、课程视频（5000+）                       |

**值得借鉴的产品机制**：

- **教师共建资源库**：化学方程式库由一线教师手工录入贡献，资源由反馈平台持续累积——学科工具 = 工具 + 资源双轮驱动，不是纯功能问题。
- **AI 备课**：输入课题/学段/重难点 → 生成教学目标、思维导图大纲、课件框架（教学大模型 2.0）。
- **板中板**：当前页叠加小黑板演算，讲完即收，不影响主课件。
- **蒙层/克隆**：揭示式板书（先遮后显），课堂互动高频。

**对云砚的启示**：希沃的学科工具全部是"白板原生元素"而非外挂窗口，可在课件页上直接使用——与我们第 4 章"课件页全工具支持"的定位一致。

### 2.2 重点深拆 B：GeoGebra（学科专用工具标杆）

**产品族**：Calculator Suite（全家桶）/ Graphing / Geometry / 3D / CAS / Scientific，网页版可嵌入（Embed options + JavaScript API）。

**核心交互**：

1. **代数区 ↔ 几何区双向联动**：每个对象既是几何图形也是代数实体，拖动图形实时改写方程，改写方程实时变形图形。
2. **对象依赖关系**：独立对象（可拖）与依赖对象（自动重算）严格区分——这是"动态几何"的引擎本质。
3. **课堂协作**：GeoGebra Classroom 让教师实时查看学生进度并给个体反馈；资源库 + LMS 集成。
4. **3D/CAS/概率**：3D 函数与曲面、符号求解（解方程/求导/积分）、概率计算器。

**授权（关键）**：**非商业使用（教师/学生/学校教学）免费；商业使用需单独授权。** 将 GeoGebra 嵌入商业产品需要与其 partnership 团队确认授权条款。

**对云砚的启示**：

- 动态几何的"约束求解 + 依赖重算"是完整引擎问题，自研成本**极大**；
- 现实可行路径是 **iframe/JS API 外挂** 或 **降级为静态图像绘制**（教师手绘 + 规整），而非复刻 GeoGebra。

### 2.3 补充拆解：ClassIn（在线小班课白板，角色模型参照）

**产品定位**：面向在线小班课的教室型白板，白板与"上台/授权"角色体系深度绑定。基于其教师使用手册拆解：

**教室工具清单**（手册原文归纳）：

- 基础：选择&移动（点选/圈选）、画笔（形状/粗细/颜色）、文本、截图（教室内/隐藏界面/二维码三种）、删除、撤销/重做、激光笔、课堂笔记（保留当前内容快照）。
- 课件：课件上传 + 动画点击触发；**50 页不间断滚动黑板**；板书保存/分享（EDB 格式，可跨课复用）。
- 互动：授权学生上台标注（授权前后工具栏切换）、花名册轮值、分组讨论室、测验/小黑板、定时器/计时器/骰子/抢答器/随机选人。
- 扩展：云盘、桌面共享、多向屏幕共享、NoBook 虚拟实验（第三方 STEM 外挂）。

**对云砚最有价值的三个设计**：

1. **"授权前后工具栏切换"**：学生被授权即获得标注工具集，收回即恢复——这是"学生上台"最克制的实现范式（本项目远期归入 §7 Won't"全员协同编辑"项一并重评估，本表仅作参考实现记录）。
2. **板书作为可保存/可分享的文档**：EDB 板书文件与课件分离管理，教师可二次编辑——对应我们 F6.3"板书快照历史"的形态。
3. **第三方实验外挂（NoBook）**：验证了"重学科能力靠外挂而非自研"的行业通行做法（我们 F3.5/F3.7 的方案 D 路线）。

**差异点**：ClassIn 白板本身**没有学科工具**（无公式/几何/函数），学科能力完全依赖外部资源——说明"学科工具"并非在线教室的必选项，而是教学白板（希沃形态）的差异化项；我们按"教学白板"定位，仍应建设 C1/C2/C3。

### 2.5 竞品洞察（驱动功能清单的 6 条结论）

1. **学科工具是教学白板的核心差异**：希沃 19 种工具直接构成其市场地位；云砚"只有笔和形状"在教学场景属于同质化底线。
2. **课件（PPT）是教师迁移成本的锚点**：所有竞品都把"PPT 进得来、在 PPT 上能圈画"作为第一体验；我们已定"课件页与空白页工具无差别"为产品目标。
3. **板书持久化/回放是国内教学白板的标配**：希沃笔迹保存、ClassIn 板书保存 + 课堂录制——我们 D1 缺失属于**基线欠账**而非新需求。
4. **学生参与是下一代差异点**：ClassIn 授权上台、GeoGebra Classroom 学生进度、希沃课堂活动；本项目已定本阶段"仅教师书写"，学生参与归入 §7 Won't"全员协同编辑/学生上台"项，远期重评估。
5. **换引擎有隐性授权成本**：tldraw 生产环境需商业授权（100 天试用后必须购买或加水印）、GeoGebra 商用需授权；Excalidraw 为 MIT 但手绘风格与"精确教学板书"调性不符且无多页。
6. **动态数学（拖拽联动）是自研最大深坑**：GeoGebra 的代数-几何联动是引擎级能力，务实做法是"外挂或静态降级"，不是排进常规迭代。

### 2.6 通用白板逐个简评（Miro / Excalidraw / tldraw）

**Miro**

- 定位：企业协作 SaaS（VC 融资、估值 175 亿美元级），白板 + 模板 + 150+ 集成 + Miro AI。
- 与我们的关系：**形态不可比**（无限画布、无教学分页与课件），仅作"协作白板上限"参照；不可自托管，排除私有化部署。
- 借鉴点：无限画布上的框架模板思路（可转化为我们的"板书模板/课堂结构模板"，属 Could 级）。

**Excalidraw**

- 定位：手绘风开源白板（MIT，可商用），React 组件，导出 PNG/SVG/.excalidraw 开放格式，内置 E2E 加密协同。
- 强项：草图沟通体验、开箱即用的协作、零授权成本。
- 弱项（对我们）：无多页概念、手绘风与课件精确标注不符、自定义工具能力弱、协同为广播后写胜（不敌现有 Yjs 语义）、React 框架。
- 结论：作为**画布技术参考**有价值（如笔迹渲染、导出管线），不作为替换方案。

**tldraw**

- 定位：无限画布 SDK（React），ShapeUtil 自定义形状 + 完整自定义工具体系，面向"嵌入自家产品"，多页/绑定内建，生态提供 Yjs Store 集成路径。
- 强项：若从零做嵌入式白板，它是工程完成度最高的商业 SDK（点击案例：ClickUp 用其替换自研白板）。
- 弱项（对我们）：**生产环境必须持 license key**（试用 100 天 / 商业付费 / hobby 带水印）、React 框架、现有 Yjs 协议与课件链路全部重写。
- 结论：列为未来"备课端全新白板"的首选备选（需预算），本轮不迁移（第 5 章）。

### 3.2 学科需求速写

> 每科按"典型课堂场景 → 当前白板的痛点 → 白板应具备的能力"展开；能力编号指向第 4 章。

**语文**

- 典型场景：课文精读圈画（关键词、修辞、段落层次）、文言文逐字注释、作文片段批改讲评。
- 痛点：现有画笔会盖住课件文字；逐字注释需要引线与小字标注，文本工具不支持富文本排版。
- 诉求：荧光笔（F4.1）、引线标签（F3.2）、文本增强（F4.3）、课件页流畅圈画（F5.1）；进阶为田字格/笔顺（F1.4、F1.5）。

**数学**

- 典型场景：代数推导（公式逐步变形）、几何证明（图形 + 标注 + 度量）、函数性质探究（坐标系 + 图像）。
- 痛点：公式完全无法输入（现在只能用文本近似）；无坐标系与几何工具，教师只能提前截图粘贴。
- 诉求：公式对象（F1.1）、符号面板（F1.3）、坐标系与函数图像（F2.1、F2.2）、几何作图与度量（F2.3、F2.4）、图形规整（F4.2）。

**英语**

- 典型场景：单词听写与音标板书、语法结构划线分析（主谓宾标注）、阅读理解定位。
- 痛点：无四线三格背景；长文本排版能力弱。
- 诉求：四线三格模板（F1.4）、公式面板中的音标/符号（F1.3）、文本增强（F4.3）、荧光笔定位（F4.1）。

**物理**

- 典型场景：受力分析（画物体 → 画力箭头 → 标大小）、电路连接与讲解、运动图像（v-t / s-t）绘制、公式推导含单位换算。
- 痛点：受力箭头要"画箭头 + 单独打字 + 对齐"三步；无坐标系；无电路元件。
- 诉求：受力箭头模板（F3.1）、坐标系（F2.1、F2.2）、公式（F1.1）、电路图（F3.4，Q1 已定外挂）或外挂仿真、器材素材（F3.3）。
- 明确不承接（评审补录）："单位换算"不设独立工具——由 F4.3 文本 + 系统计算器近似覆盖，记入延后项清单（第 11 章）。

**化学**

- 典型场景：方程式书写（含条件、气体/沉淀符号）、实验装置讲解、物质转化关系。
- 痛点：方程式只能手写或贴图，无法排版与配平演示。
- 诉求：mhchem 方程式（F1.2）、配平辅助（F3.6）、装置图素材 + 引线标注（F3.3、F3.2）、分子结构（F3.5 远期）。

**生物**

- 典型场景：细胞/器官结构认识（底图 + 逐个引线标注）、生理过程流程、遗传棋盘表格。
- 痛点：无引线标注、无表格，标注全靠画笔手写，位置易乱。
- 诉求：引线标签（F3.2）、表格（F4.4）、结构底图素材（F3.3）、流程箭头（已有箭头工具 + F3.1 组合模板）。

**历史**（低优先）

- 典型场景：时间轴梳理朝代/事件、史料图片批注、地图疆域标注。
- 诉求：表格/时间轴近似（F4.4、F4.7）、图片标注（F4.6、F3.2）；坐标系仅用于年代尺的降级使用（F2.1）。
- 近似形态写死（评审补录）：时间轴以"表格分段行式"呈现（每行一个朝代/事件段），可感知但**非拖拽式时间轴**——记入延后项清单（第 11 章），走查若反馈刚需则经变更流程评估 F2.1 拓展或新项。

**地理**（低优先）

- 典型场景：经纬网与地图判读、地形剖面、气候资料图。
- 诉求：坐标系/网格（F2.1）、图表表格（F4.4）、地图素材与标注（F3.3、F3.2）。

**道法**（低优先）

- 典型场景：概念关系梳理、案例材料圈画。
- 诉求：思维导图（F4.7）、荧光笔与文本（F4.1、F4.3）。

### 4.1 C1 公式与符号表达

**F1.1 公式对象（LaTeX / KaTeX）** ｜ `Must` ｜ 成本:中（区间上限；渲染方案 spike 后回写，若仅做纯 LaTeX 源码框则降"小-中"） ｜ 数/物/化/英 ｜ 课件页:✓

- 描述：白板原生"公式元素"，LaTeX 源码输入 → KaTeX 渲染为可移动、缩放、删除的独立对象，进入 Yjs elements 同步给学生。
- 交互写死：工具栏"∑"按钮或快捷键呼出输入浮层；**浮层状态机**：默认 → 输入中 →（语法错误：输入框红框 + 行内可读文案）→ 渲染中（chunk 占位）→ 已提交（自动关闭）；Esc=取消、Enter=提交、双击已有公式重新编辑；学生只读端不可呼出编辑（进只读矩阵）。渲染实现方案以 5.7.1 spike 结论为准回写，**不保留"或"**。
- 依赖：新增 `katex`（**附加因子**：katex.min.js ≈280KB + 公式必需字体 woff2 合计 ≈300KB，**JS+字体 ≈600KB，以实测为准**；JS 可按需 chunk，字体走子集/懒加载策略）；新增 element type `formula`；渲染方案 spike 前置（见 5.7.1，原"转 SVG"路线因 KaTeX 无 SVG 输出已否决）。
- 备注：**这是数学/物理教学的第一刚需**，也是竞品（希沃公式编辑器、GeoGebra 输入栏）的标配。

**F1.2 化学方程式（mhchem 扩展）** ｜ `Should` ｜ 成本:小 ｜ 化 ｜ 课件页:✓

- 描述：在 F1.1 基础上启用 KaTeX `mhchem` 扩展，支持 `\ce{}` 语法（气体↑、沉淀↓、条件符号、配平）。
- 交互：同 F1.1，公式面板增加"化学模式"预设。
- 依赖：F1.1；额外包体极小。

**F1.3 符号快捷面板** ｜ `Should` ｜ 成本:小 ｜ 数/物/英 ｜ 课件页:✓

- 描述：常用符号一键输入：≥ ≤ ± × ÷ ∠ ∥ ⊥ ≌ ∑ ∫ √ π α β Δ → ⇌ 等按学科分组；**新增"国际音标"分组**（iː ɪ e æ ɑː ɒ ɔː ʊ uː ʌ ə ɜː θ ð ʃ ʒ ŋ tʃ dʒ 等，服务 3.2 英语"单词听写与音标板书"诉求）。
- 交互：公式输入浮层内的符号页签，点击插入光标处；分组页签：通用数学 / 物理 / 化学 / 音标。

**F1.4 四线三格 / 拼音格模板** ｜ `Could` ｜ 成本:中 ｜ 英/语 ｜ 课件页:✓

**F6.4 时间轴过程回放** ｜ `Could` ｜ 成本:大 ｜ 全科 ｜ 课件页:N/A

- 描述：记录笔迹事件时序，支持拖动进度条"重放书写过程"（板书推演过程可反复观看）。
- 交互：回放视图 + 播放/暂停/倍速/进度拖动。
- 实现要点：需新增事件流日志（append-only）+ 播放器；**Yjs update 二进制不含时间戳**——须在元素/事务上带时间字段或服务端记录 update 到达序列（属协议改动，成本"大"的隐含前置）；带宽与存储随课时线性增长。

## 5. 技术路线评估

### 5.1 约束与前提

- **前端栈为 Vue 3 + Electron**（非 React）。
- **Yjs 协议已成型**：pages/elements/viewport/toolState/fileList + awareness（激光/光标），学生只读跟随语义已实现并有测试覆盖。
- **课件链路**（PPT→PDF→ppt-image 元素）与白板渲染深度耦合。
- **部署约束（评审新增）**：yjs-ws-service 为单进程内存 Map、无跨实例广播——本报告全部服务端方案按**单实例假设**设计，多实例快照一致性属扩容议题（见 5.9.1）。
- 无既定换引擎约束，允许客观评估（但结论需给出成本依据）。

### 5.2 方案 A：继续 Konva 自研（分层外挂领域库）

- 做法：白板本体（画布/工具/同步/课件）继续自研；**领域能力用成熟库补齐**——公式用 KaTeX、表达式解析用 mathjs、素材/3D 用开源渲染外挂。
- 优势：零授权成本；完全掌控 Yjs 协议与角色语义；课件页/视口/undo 不动；渐进演进（每条功能独立可交付）；团队已熟悉。
- 劣势：每类工具都要自己做交互与渲染（几何、导图、表格的交互细节工作量大）；`@ts-nocheck` 大文件需逐步治理。
- 成本档：与第 4 章各项成本一致，无额外迁移成本。

### 5.3 方案 B：换 tldraw（嵌入式画布 SDK）

- 事实：React SDK；形状系统（ShapeUtil）与自定义工具成熟；官方生态提供 Yjs Store 集成方案；多页、绑定（箭头吸附）内建。
- **授权**：source-available，**生产环境必须持有效 license key**——商业授权付费（或 100 天试用/带水印的 hobby license）。
- 劣势：① React 与 Vue 并存（需 `react-in-vue` 桥或 iframe 隔离，双框架 bundle 与事件互通成本）；② 现有 Konva 渲染、课件元素、视口同步、undo 全部重写；③ 团队学习曲线；④ 商业授权引入长期依赖。
- 估算：整体迁移属"极大"（数月级），期间教学功能停摆。

### 5.4 方案 C：换 Excalidraw（MIT 开源白板）

- 事实：MIT，可商用；React 组件；手绘风格；内置广播式协同（后写胜）。
- 劣势：① 同样是 React（Vue 桥接问题；**但亦可以 iframe 外挂规避框架冲突**——方案 D 已验证该路径，结论不变：仍输在无多页与自定义工具弱）；② **无多页概念**（教学分页需自造 frame 方案）；③ 手绘风与"精确教学板书/课件标注"调性不符；④ 自定义工具能力弱于 tldraw；⑤ 现有 Yjs 协议与课件链路同样推倒重来。
- 结论：除非"整体重做白板"，否则不构成正收益。

### 5.5 方案 D：混合外挂（白板自研 + 领域能力外挂窗口）

- 做法：公式/坐标系等**页内原生元素**走方案 A；3D 模型、电路仿真、（如需要）GeoGebra 等**重引擎**以 iframe/弹窗"共享视图"外挂，状态同步仅同步"打开与否 + 参数"。
- 优势：以最小成本触及引擎级能力；风险隔离。
- 劣势：外挂窗口与笔迹层无法互相标注（可在截图后降级为"截入白板标注"弥补）。
- 授权提醒：GeoGebra 商用需授权；选用开源外挂（3Dmol/Falstad 类）需做许可审查。

### 5.6 对比与建议

| 维度             | A 自研+外挂库 | B tldraw       | C Excalidraw | D 混合外挂       |
| ---------------- | ------------- | -------------- | ------------ | ---------------- |
| 框架匹配         | ✅ Vue 原生   | ❌ React       | ❌ React     | ✅               |
| 授权成本         | ✅ 无         | ❌ 生产付费    | ✅ MIT       | ✅ 需逐项审查    |
| 现有 Yjs/课件    | ✅ 保留       | ❌ 重写        | ❌ 重写      | ✅ 保留          |
| 学科工具产出速度 | 中（逐项做）  | 中（迁移后快） | 慢           | 快（重能力外挂） |
| 长期维护         | 自担          | 依赖上游+授权  | 依赖上游     | 自担+外挂维护    |

**建议：以方案 A 为基线、按需叠加方案 D**，即"自研白板 + KaTeX/mathjs 等页内库 + 重引擎外挂窗口"。换引擎（B/C）本轮不做；若未来立项"备课端全新白板"，再重新评估 tldraw（预算含商业授权）。

### 5.7 方案 A/D 的关键设计要点

1. **公式渲染与视口同步（评审修正）**：**KaTeX 仅有 HTML/MathML 输出，无原生 SVG**——"渲染为 SVG 作为 Konva Image"不成立（需 HTML→SVG/位图转换或更换渲染器，附带依赖与许可成本）。**首选方案 = stage 同级 DOM overlay**：与 Konva stage 共享同一套 `scale/offset` 变换、统一 pointer-events 管理、与 Konva 选中框/Transformer 互斥（选中公式时隐藏 DOM 层命中区）、z-order 规则写死（公式层位于笔迹层之下或之上需按绘制顺序动态排布）。**F1.1 立项前必须先做渲染方案 spike（overlay vs 光栅化入 Konva Image 二选一），结论回写本节**；该 spike 直接决定 F1.1 成本档（当前"中"取区间上限）。
2. **元素类型注册表**：新增 element type（`formula`/`grid`/`curve`/`table`…）时统一走 `KonvaRenderer` 工厂（现有形状 switch 位于 `KonvaRenderer.ts:367-489`，`default` 静默 `return null`）。**评审加码**：`types.ts` 目前只有 `ToolState`，元素 type 是裸 string、且 mode 与 element 是**双套命名**（`rectangle` vs `rect`）——须增列独立技术项：`ElementType` 联合类型 + mode↔element 显式映射表 + `createNode` 穷尽性检查（未知类型走显式 `unknown` 分支）、消化 D3；**此项收益依赖 D6 摘除 `@ts-nocheck`**，顺序为 D6 → D3 → 新元素类型。每新增一个 element type 按 8.1 类型/测试检查清单验收。
3. **外挂窗口的状态同步**：iframe 外挂不进 Yjs 文档，仅同步"页内挂点元素（记录 iframe URL/参数/位置）+ 打开状态"；**介质定死**：挂点与参数入 **Y.Map（持久，进快照、进 undo）**，"当前打开态"入 **awareness（瞬时，恢复即关）**，并写明降级行为。学生端点同一挂点即打开同一视图。截图回填（F4.6）作为外挂内容进入板书的补救通道。
4. **持久化格式与介质**：快照采用 `Y.encodeStateAsUpdate` 原生二进制，避免 JSON 序列化丢类型；**介质、写入路径、触发点、保留策略的完整设计见 5.9.1**（事实：现有服务无 DB 依赖，须显式接入）；存储保留"最近 N 次课"滚动窗口 + 课程维度归档，兼顾 D7 内存回收与 F6.3 历史。课次身份须由网关下发 lessonId（"房间空 ≠ 下课"）。
5. **性能护栏（常规办公机、≤50 人假设，评审补 2 项硬前置）**：
   - **增量渲染（新增，前置项）**：现状 `bindElements` 每次 `nodeMap.clear()` + `layer.destroyChildren()` 全页重建（`KonvaRenderer.ts:238-261`，由 `WhiteBoard.vue:483-495` observeDeep 触发）——任意一笔 O(全页元素) 重建；须演进为元素级增量 diff（仅重建变更 id）或按事务合并节流刷新。验收：长板书（≥500 笔）连续书写学生端帧率 ≥30fps。
   - **课件内存（新增，前置项）**：`pdfAsset.ts:41-60` 的 `renderCache` 为无驱逐 Map（scale=3 单页 ≈9MB，100 页≈数百 MB 永不释放）+ 每页预建独立 Konva.Layer 常驻——须 LRU/按可见页释放 + 非活动页 Layer 回收（或延迟建层）；本节"layer 缓存"仅限**内容层子集**，不叠加含底图的整页位图副本。
   - 既有项：荧光笔/大图形批量绘制走 layer 缓存；光标 awareness 节流 30–60ms（写侧同步加节流，D2）；函数曲线采样点数随缩放动态调整；导出走离屏 stage 复用。
   - Y.Doc 无界增长护栏：快照时评估 `Y.mergeUpdates` 压实 + 文档体积告警阈值。

### 5.9 快照存储、回看鉴权与接口契约（评审新增，F6.2/F6.3 前置设计）

**5.9.1 存储设计**（事实：`yjs-ws-service/package.json` 仅 ioredis，**无任何 DB 客户端**，仓库无对象存储——"复用现有基建"不成立，须显式接入）

- **介质选型（二选一，Q8 拍板）**：① 新增 DB 表 `board_snapshot(id, room_id, lesson_id, format_version, data bytea, created_at)` + `(room_id, created_at)` 复合索引（与 live-service 共库，简单、事务一致）；② 文件/对象存储 + 元数据表（大快照友好，但需引入对象存储基建）。倾向 ①，成本计入 F6.2 升档触发条件。
- **写入路径二选一**：yjs-ws 直连 DB（依赖新增，进程内闭环）或经 live-service gRPC（复用 `SaveCourseware` 模式，契约多一跳）。**倾向经 live-service**，与现有服务分层一致。
- **写入触发点（四类）**：下课事件（课次身份由网关下发 lessonId 或课次结束通知——"房间空≠下课"，不能仅靠空房判定）、定时（每 N 分钟增量快照）、服务重启前（SIGTERM handler 刷盘，现状 `main.ts:309-313` 不 flush）、空房清理前（**D7 前置条件**）。
- **保留策略**：滚动窗口"最近 N 次课/每班"（N 由 Q8 拍板，默认 10 次课）+ 课程维度归档任务；容量量级估算（**需实测校准**）：单页密集板书 ≈ 数十 KB 二进制，单课（20 页）≈ 1–5MB，单班学期（60 课）≈ 0.1–0.3GB——按 ① 介质完全可承受。
- **文档体积护栏**：长课时 Y.Doc tombstone 累积，快照写入时评估 `Y.mergeUpdates` 压实 + 文档体积告警阈值。
- **已知约束**：yjs-ws-service 为**单进程内存 Map**（无跨实例广播），本方案按单实例部署设计；多实例化时的快照一致性/写者分片属扩容议题，超出本轮范围（见 5.1 约束）。

**5.9.2 回看鉴权**（F6.3 上线硬前置，Q9 拍板）

- **授权模型**：教师 = `live_rooms.liveUserId` 匹配；学生 = `live_participants` 成员存在性校验（已有 `Unique(userId, roomId)`）；快照接口统一 JWT + **房间级 403**。
- **角色权限矩阵**（同时写入 4.8 五维-权限）：教师 = 导出 + 回看 + 清页 + 回放控制；学生 = 只读回看**本班**（不开导出）；家长 = 不提供入口；保留期限由 Q8 拍板并提供删除权。
- **关联修复项**（存量越权，若不修则 F6.3 复刻同模式）：`coursewareList/deleteCourseware` 仅 JwtAuthGuard（任意 roomId/id 可操作，`live.controller.ts:670-693`）、`/uploads` 静态目录与 `/upload/*` 无鉴权（`server/src/main.ts:29`、`upload.controller.ts:38,69`）。
- **D8 联动**：yjs-ws 握手期按角色过滤 sync 写消息 + 房间成员校验，与 F6.2 同批上线。

## 6. AI 能力前瞻（不入主清单）

以下能力依赖外部模型服务、与离线/私有化部署目标可能冲突，仅作前瞻记录，**不进入第 7 章 MoSCoW 清单**：

| 方向             | 描述                                                  | 主要依赖/风险                            |
| ---------------- | ----------------------------------------------------- | ---------------------------------------- |
| 手写公式识别     | 手写笔迹 → LaTeX 自动转公式对象                       | 端侧模型体积 / 识别准确率                |
| 智能图形规整升级 | 从"几何拟合"升级为"草图语义识别"（如识别箭头/坐标系） | 模型服务；F4.2 的静态版可先行            |
| 板书转讲义       | 下课后板书 + 页序 → 结构化复习讲义                    | LLM 服务；依赖 F6.2 持久化               |
| AI 备课生成      | 输入课题 → 教学目标/课件框架（对标希沃 AI 备课）      | 教学资源与提示工程；属备课端而非白板本体 |
| 作业/板书批改    | 学生图片或板书批注自动批改                            | 准确率责任边界；需产品侧定义             |

**结论**：AI 前瞻的共同前置是 **F6.2 板书持久化**——先把数据留下，AI 才有机会介入。

**合规红线（评审新增）**：AI 任何试点（板书转讲义/批改/识别）会将课堂内容（可能含学生个人信息）送出域，与私有化部署目标存在冲突——**须先过数据出域审批 + 私有化模型评估 + 内容安全基线**，未过不得接入；准确率类功能（批改）须由产品侧定义责任边界后方可立项。

## 9. 边界说明

- **相邻机会（不在本清单）**：答题卡/随堂测、随机选人、计时器等课堂互动工具属独立功能域，若立项应单独立项评审（竞品均将其与白板并列而非混入）。

- **不做的事**：本轮不整体替换白板引擎（第 5 章结论）；不做教师访谈之外的需求臆断（第 3 章风险已声明）；不做 AI 数据出域（未过第 6 章合规红线）。
