# F5.4 课件导入保真增强 — 转换方案评审文档

> 状态：方案评审稿（本轮唯一交付物，不含代码改动）
> 依据：`docs/research/whiteboard-teaching-features.md` §4.5 F5.4（规格原文"属课件链路而非白板本体，单独立项评审"）；`docs/research/stage4-portfolio-review.md` 第 170-177 行（DoD 草案：另立方案文档 + 转换样例集基线；红灯 spec 2 条）
> 关联：F5.1 课件页底图管线（转换产物的消费方）

## 1. 背景与目标

PPT 上传后在网关（`apps/server`）同步转换为 PDF，作为白板课件页底图。当前实现是最小可用形态，版式/字体保真存在已知损失。F5.4 的目标不是替换整条链路，而是：在离线部署约束下，把"能打开"提升到"教师可上课"的版式保真度，并把失败路径从静默降级改为可诊断、可提示。

非目标（本轮明确排除）：

- PPT 动画保真。PDF 是静态分页格式，动画无法进入底图；动画保留需要原格式渲染引擎（如 PPTX 前端渲染库），属独立立项。
- 云端转换 API（CloudConvert 等）。与离线部署/数据不出境约束冲突，仅在对比表中登记。
- 转换后二次编辑（PPT 内容退回白板可改对象），成本与 F5.1 架构冲突。

## 2. 现状链路与边界

代码位置（行号基于当前分支）：

| 环节         | 位置                                                       | 现状                                                                             |
| ------------ | ---------------------------------------------------------- | -------------------------------------------------------------------------------- |
| 参数构造     | `apps/server/src/upload/ppt-convert.ts:3-5`                | 5 行：`--headless --convert-to pdf --outdir`，无任何保真参数                     |
| 执行与超时   | `apps/server/src/upload/upload.controller.ts:105-121`      | `execFileAsync` 同步等待，`PPT_TO_PDF_TIMEOUT_MS = 120000`（`ppt-convert.ts:1`） |
| soffice 定位 | `upload.controller.ts:106-110`                             | `SOFFICE_PATH` 环境变量优先，否则 win32 默认安装路径 / PATH 中 `soffice`         |
| 成功判定     | `upload.controller.ts:117-119`                             | 仅检查输出 PDF 是否存在，无内容校验（空页/全白 PDF 视为成功）                    |
| 失败降级     | `upload.controller.ts:122-129`                             | 捕获后 `return { fileUrl: '' }`——**空 URL 静默失败，与"成功但 URL 空"不可区分**  |
| 测试基线     | `ppt-convert.spec.ts`（2 条）+ `upload.controller.spec.ts` | 仅断言参数形状与超时常量，无保真断言                                             |

已知保真损失（按教师感知度排序）：

1. **字体替换**。转换机未安装课件所用字体时，LibreOffice 用系统近似字体替换，字宽/换行漂移导致版式错位。Windows 默认安装目录下的 LO 不含中文字体补齐策略；Linux 容器通常只有 Noto 基础集。
2. **母版/主题元素丢失**。复杂母版（背景图片叠层、斜切装饰、渐变文本框）在 LO Impress 导入器中偶发丢失或错位。
3. **SmartArt / 高级图形**。LO 对 SmartArt 支持为"尽力渲染"，层级着色与立体效果降级明显。
4. **公式与图表**。OMML 公式经 LO 转换可能错行；原生图表（Excel 嵌入）转为静态图后分辨率取决于导出 DPI。
5. **并发与资源**。同步 `execFile` 在大文件（>50MB）或多教师同时上传时占满 LO 进程资源；120s 超时对美术类大课件不够。

## 3. 候选方案对比

### A. LibreOffice 参数调优（推荐首期）

- `--convert-to 'pdf:impress_pdf_Export'` + FilterOptions 显式控制导出质量（嵌入字体开关、JPEG 质量、DPI）。
- 效果：解决损失 4（DPI/JPEG 参数化）；对损失 1 仅在"字体已装在转换机"前提下有效——**参数调优不能凭空创造字体**。
- 成本：小-中。改动集中在 `ppt-convert.ts` 参数构造 + spec 更新；部署侧无新依赖。
- 风险：FilterOptions 语法版本敏感（LO 7.x/24.x 差异），需在样例集上锁定版本。

### B. 转换机字体补齐（与 A 绑定，推荐同期）

- 部署文档规定字体最小集（中文：思源黑体/宋体、方正基础教育字库视采购而定；西文：Arial/Times 等宽替代表）；Linux 容器安装 `fonts-noto-cjk` 等基础包；Windows 部署要求转换目录可访问系统字体。
- 效果：直接解决损失 1、部分解决损失 2（母版字体相关错位）。
- 成本：小（文档 + 镜像/Dockerfile 调整），但**采购字体有法务边界**——方案文档不预设具体商业字体，留给实施时确认。
- 风险：字体目录与 LO fontconfig 缓存刷新（`fc-cache`）在容器冷启动时的时序。

### C. 替代转换引擎（对比登记，本期不推荐）

| 工具             | 保真度         | 部署形态    | 许可                      | 结论                                                                 |
| ---------------- | -------------- | ----------- | ------------------------- | -------------------------------------------------------------------- |
| unoconv          | 与 LO 同源     | Python 包   | GPL                       | 无增量价值，排除                                                     |
| ONLYOFFICE 转换  | 对 MS 格式更好 | 服务化/容器 | AGPL（服务端）/商业双许可 | 保真提升真实，但 AGPL 服务端义务与现有 Nest 栈整合成本高，留二期评估 |
| Aspose.Slides    | 高             | 商业库      | 商业许可（按席位/服务器） | 付费门槛；先用 A+B 量化差距再决定是否值得买                          |
| CloudConvert API | 高             | 云端        | 按量计费                  | 与离线部署/数据不出境冲突，排除                                      |

### D. 失败路径改造（推荐首期，独立于 A/B 可先做）

- 转换失败/超时/产物缺失不再返回 `fileUrl: ''`，改为结构化错误：`{ code, msg: 'CONVERT_FAILED', data: { stage, retryable } }`，由 desktop 弹窗提示"课件转换失败，可下载原 PPT 本地打开"并附原文件下载链接（原 ppt 文件已落盘，直接出静态路由）。
- 成本：小。controller 返回结构 + desktop 上传组件错误分支 + 各 1-2 条 spec。

## 4. 转换样例集与基线设计

目的：让"保真提升"可测量，而非主观感受。样例集入库 `apps/server/test/fixtures/courseware/`（二进制小文件，单个 < 2MB，总量控制 < 20MB）。

样例分类（每类 1-2 个文件，合成构造优先，避免真实课件版权）：

| 类别      | 覆盖损失点 | 构造要点                                                          |
| --------- | ---------- | ----------------------------------------------------------------- |
| 字体-缺失 | 1          | 指定小众字体文本框，转换机不装该字体                              |
| 字体-已装 | 1          | 同内容改用思源黑体，验证替换前后版式一致性                        |
| 母版-复杂 | 2          | 多层背景 + 斜切装饰 + 渐变标题                                    |
| SmartArt  | 3          | 层级图、循环图各一                                                |
| 公式-密集 | 4          | 多行 OMML 公式混排                                                |
| 图表-嵌入 | 4          | 嵌入 Excel 柱状/折线各一                                          |
| 动画-声明 | —          | 带动画声明的页，断言转 PDF 后为首帧静态页（预期行为，防回归误报） |

基线与评审流程：

1. **自动基线**：转换脚本（vitest 集成测试，标记 `courseware-fidelity`，默认跳过、CI 手动触发）对样例集逐个转换，记录：转换是否成功、耗时、输出 PDF 页数、每页渲染 PNG（pdfium/poppler 预装）的感知哈希。页数与 PDF 可解析性为硬断言；感知哈希与上次基线 JSON 对比，偏差超阈值仅告警不失败（人工复核入口）。
2. **人工评审**：每季度或 LO 版本升级时，打开基线 PNG 与原 PPT 截图并排比对，填写偏差表（错位/缺字/丢元素三级）。评审记录入 `docs/research/courseware-fidelity-review.md`。
3. **版本锁定**：部署文档写死 LO 主版本（如 24.2 LTS），升级走样例集全量回归。

## 5. 失败降级状态矩阵

| 场景                     | 现状行为               | 目标行为                                                            |
| ------------------------ | ---------------------- | ------------------------------------------------------------------- |
| soffice 未安装（ENOENT） | `fileUrl: ''` 静默     | `CONVERT_FAILED/retryable:false` + 前端提示安装指引（运维文档链接） |
| 转换超时（120s）         | `fileUrl: ''` 静默     | `CONVERT_FAILED/retryable:true` + 前端"重试"按钮（限 1 次）         |
| 退出码 0 但无 PDF        | throw 后同样空 URL     | `CONVERT_FAILED/retryable:false` + 附 LO stderr 摘要入日志          |
| 转换成功但页数为 0/损坏  | 视为成功               | 内容校验（PDF 头 + 页数 > 0），失败按上行处理                       |
| 部分页渲染全白           | 视为成功               | 本期不拦（自动白页检测误伤纯白底课件），人工评审记录                |
| 客户端收到空 fileUrl     | 上传"成功"、课件页空白 | 前端显式错误态 + 原 PPT 下载兜底入口                                |

## 6. 同步 → 异步评估

现状：`upload.controller.ts` 内联同步 `execFileAsync`，HTTP 请求最长挂起 120s，前端上传超时风险与 LO 并发争用叠加。

| 维度     | 同步（现状）                  | 异步（任务队列 + 轮询/WS 通知）                         |
| -------- | ----------------------------- | ------------------------------------------------------- |
| 实现成本 | 0                             | 中-大（队列表、worker、状态机、前端轮询）               |
| 体验     | 大文件长时间无反馈            | 上传秒回 + 课件页"转换中"占位（复用 F5.2 生成中态模式） |
| 并发     | LO 进程无排队上限，易互相拖垮 | 单 worker 串行或限流，天然排队                          |
| 失败重试 | 需前端整单重传                | 任务级重试，不动已上传文件                              |

**建议**：首期维持同步但收紧（超时降到 60s + 重试按钮），异步队列排在保真度 A+B/D 落地之后——否则异步化只是把不可靠的转换更快地排队。异步化立项时应复用 `apps/server` 已有任务形态（若有）而不是新造框架。
