## 3. 信任边界与关键结论

```
公网 HTTP/WS ──> gateway(:3001) ──> gRPC(auth:50051 / live:50052 / mail:50053)   ← 内网，当前 insecure + 0.0.0.0 绑定
公网 WS ──────> chat-ws(:50054) / yjs-ws(:50055)（自带 JWT+Redis 会话校验）
```

三条定论（评审收敛，写入即约束后续设计）：

1. **房间归属校验的唯一落层 = live-service 域层**（gateway 只透传身份）。gateway 侧校验仅作补偿控制，
   在 `GAP-S10b`（gRPC 身份可信）落地前，`user_id` metadata 属自称，域层校验的信任根不完整——
   S4 降级方案：先做 gateway 侧归属校验 + 记为补偿控制，S10b 完成后下沉域层。
   （**闭环**：S10b ✅ 2026-10-20 → S4 域层下沉 ✅ 2026-10-21，见 GAP-S4 行。）
2. **`/uploads` 静态目录（`apps/server/src/main.ts:31,37`）与上传 POST 接口是两个独立缺口**，
   读写双侧都要保护；且静态目录必须保持 `Access-Control-Allow-Origin: *`（pdf.js 需 `Origin: null` 读像素），
   签名 URL 方案与该 CORS 约束存在张力 → `GAP-S3` 先出 0.5d 设计决策再动工。
3. **迁移三轨已构成破坏性冲突**（非"漂移"）：`live-service` 全环境 `synchronize: true`
   （`apps/live-service/src/app.module.ts:37`）会按 entity 元数据 **DROP 掉手工迁移建的孤儿索引**
   （如 `20260907_create_user_watch_times.sql:10-11` 的两个索引，entity 与 schema.sql 均无声明）；
   且 `20260907_migrate_timestamp_to_timestamptz.sql` 的 snake_case 列名与 `init/schema.sql:16-30`
   的引号 camelCase（`"createdAt"`）互斥，在 schema.sql 建的库上直接报列不存在。

   **→ 已处置（批次 2 / S9a，2026-10-17）**：`live-service` 默认 `synchronize: false`（`TYPEORM_SYNC` env gate，生产显式 `true` 拒启动）；schema 变更统一走 `db/migrations/` + `scripts/db-migrate.mjs`（`schema_migrations` + sha256 checksum + forward-only），`db/schema-baseline.sql` 为期望态快照并由 CI schema diff 门禁守护；`apps/*/src/migrations/`（4 文件白名单）与 `init/schema.sql` 封存。详见 `db/README.md`。

## 5. 安全专项（设计约束汇总）

1. **限流分级**（S1）：keyGenerator 必须 userId+IP 双键；认证类端点独立低阈值；禁止全接口同额度默认值。

3. **上传**（S3）：写入鉴权与静态读取保护分开验收；CORS `*` 约束下的方案必须先决策再实现。
4. **信任根**（S4/S10）：网关侧校验=补偿控制；域层校验=synchronous authority；**S4 域层下沉已完成（2026-10-21）**，房间归属校验唯一落层 live-service，网关仅保留边缘角色守卫（JWT role）与本地效果端点的 checkRoomAccess 判定。
5. **会话**（S6）：改密/重置=全端吊销（HTTP+chat-ws+yjs-ws 三链路）。
6. **法务门槛**（S11）：五个会签项分拆绑定到具体批次 DoD，不设独立"合规批次"。
